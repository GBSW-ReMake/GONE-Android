## 1. 목적 및 배경

학생이 사용 가능한 실습실을 층별로 조회하고, 대여 신청을 작성하며, 자신의 대여 신청 진행 상태를 확인할 수 있는 실습실 탭 UI를 구현합니다. 제공된 iOS 화면과 동일한 정보 구조를 Android Flutter 환경에 맞게 적용합니다.

## 2. 사용자 시나리오

```text
사용자가 하단의 실습실 탭을 선택한다
→ 날짜와 층 탭을 확인하고 대여 가능한 실습실을 선택한다
→ 선택한 실습실 정보와 대표자·사용 인원·사용 목적을 입력한다
→ 대여 신청을 완료하고 내 실습실 대여 화면에서 신청 상태를 확인한다
→ 새 예약을 눌러 실습실 목록으로 돌아간다
```

## 3. 화면 및 UX

### 실습실 목록

- 상단에 `7월 29일 실습실 예약`과 층 선택 탭(4층·3층·2층)을 표시합니다.
- 층별 사용 가능 실습실 카드에 번호, 이름, 최대 인원, 빔프로젝터 여부, 예약 가능 상태를 표시합니다.
- 선택한 실습실은 GONE 블루 외곽선으로 구분하고, 하단 CTA에 선택한 실습실명을 반영합니다.
- 실습실이 없거나 모두 대여 중인 경우 별도 빈 상태를 제공합니다.

### 대여 신청

- 뒤로가기, 제목, 선택한 실습실 요약 카드를 표시합니다.
- 대표자, 사용 인원 명단, 사용 목적 입력 필드를 제공합니다.
- 필수 값 누락·인원 초과·형식 오류에는 필드별 오류 메시지를 표시합니다.
- `대여 신청하기`는 입력이 유효할 때만 활성화합니다.

### 내 실습실 대여

- 신청 상태, 신청 번호, 실습실·시간·대표자·사용 인원·목적을 요약합니다.
- 진행 단계(신청완료 → 승인대기 → 이용가능)를 시각적으로 표시합니다.
- 대여 취소 버튼과 승인 대기 안내를 제공합니다.
- 신청 내역이 없을 때는 새 예약을 유도하는 빈 상태를 제공합니다.

### 공통 UX

- 하단 탭은 홈과 동일한 SVG 아이콘·선택 상태를 재사용하고, 실습실 탭을 선택 상태로 표시합니다.
- 모든 버튼은 48dp 이상의 터치 영역, TalkBack 레이블, 키보드 입력 시 스크롤 대응을 제공합니다.
- API 연결 전에는 화면 검토용 목 데이터를 사용합니다.

## 4. 데이터 및 아키텍처

```text
features/lab_rental/
├── domain/
│   ├── entities/lab_room.dart
│   └── entities/lab_rental.dart
├── application/
│   └── lab_rental_notifier.dart
└── presentation/
    ├── lab_rental_page.dart
    ├── lab_rental_form_page.dart
    ├── my_lab_rental_page.dart
    └── widgets/
```

- `LabRoom`, `LabRental`, `RentalStatus` Entity로 화면 데이터를 표현합니다.
- `LabRentalNotifier`는 선택한 층·실습실·현재 화면·신청 상태를 관리합니다.
- 초기에는 목 데이터와 메모리 상태를 사용합니다.
- 실제 API 계약이 확정되면 Repository 인터페이스와 UseCase를 추가해 화면 상태와 데이터 접근을 분리합니다.
- 대표자·인원·목적 검증은 View가 아닌 Notifier 또는 UseCase에 둡니다.

## 7. 제한사항 및 결정 필요 항목

- 실제 대여 가능 시간, 취소 정책, 승인 권한은 API 정책 확정 후 연결합니다.
- 현재 디자인의 대표자 입력 예시는 이름/학번 구분이 불명확하므로, UI 단계에서는 문자열 입력으로 처리하고 API 계약 후 모델을 확정합니다.
- 실습실 탭 외의 상세 기능 연결은 이번 작업 범위에 포함하지 않습니다.
