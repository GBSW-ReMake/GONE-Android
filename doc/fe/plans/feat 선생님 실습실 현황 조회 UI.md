## 1. 목적 및 배경

현재 Android 선생님 실습실 탭은 학생용 실습실 대여 신청 흐름을 그대로 사용하고 있습니다. 선생님에게는 학생들이 신청한 실습실을 층별·날짜별로 확인하고 예약 상세를 조회하는 현황 화면이 필요하므로, iOS에 구현된 선생님 실습실 현황 조회 UX를 Android Flutter 화면으로 동일한 정보 구조와 비슷한 크기로 구현합니다.

학생용 실습실 신청 화면은 유지하고, 계정 역할에 따라 선생님에게만 현황 조회 화면을 제공합니다.

## 2. 사용자 시나리오

```text
선생님이 하단의 실습실 탭을 선택한다
→ 날짜별 실습실 현황과 층 선택 영역을 확인한다
→ 4층·3층·2층 중 층을 선택한다
→ 실습실별 예약자·사용 목적·야자시간/방과후/미예약 상태를 확인한다
→ 예약된 실습실 카드를 누른다
→ 예약 상세 화면에서 날짜·실습실·이용시간·대여자·사용 목적·사용 위치를 확인한다
→ 뒤로가기로 현황 목록으로 돌아온다
```

## 3. 화면 및 UX

### 선생님 실습실 현황 목록

- 기존 Android 실습실 대여 화면의 상단 여백, 좌우 여백, 카드 크기를 기준으로 iOS 선생님 현황 화면과 유사한 비율을 적용합니다.
- 상단에는 `실습실 대여` 보조 문구와 `7월 29일 실습실 현황` 형식의 날짜 제목을 표시합니다.
- 날짜 선택 컨트롤은 목록 조회 범위를 벗어나지 않도록 우선 현재 목 데이터 날짜를 표시하고, 실제 날짜 API/정책이 확정되면 선택 기능을 확장합니다.
- 층 선택은 4층·3층·2층의 둥근 세그먼트 UI로 구성합니다.
- 선택된 층은 흰색 선택 영역, GONE 블루 텍스트, 볼드 서체로 표시하고 바깥 영역은 상벌점 화면과 동일한 연한 회색을 사용합니다.
- 층 제목과 예약 수를 표시한 뒤 실습실 카드를 세로 목록으로 배치합니다.
- 카드에는 실습실 번호, 실습실명, 예약자 요약, 사용 목적, 이용 시간 상태 태그를 표시합니다.
- 상태 태그 색상은 야자시간은 블루, 방과후는 노란색, 미예약은 중립 회색으로 구분합니다.
- 예약된 카드만 상세 화면으로 이동하며, 미예약 카드는 조회용 비활성 상태로 표시합니다.
- 실습실 목록이 비어 있거나 조회 오류가 발생하면 빈 상태·오류 상태와 재시도 동작을 제공합니다.

### 선생님 실습실 예약 상세

- 상단 뒤로가기와 실습실명을 표시합니다.
- 이용 유형 태그, 날짜, 실습실명, 이용시간, 대여자, 사용 목적, 사용 위치를 왼쪽 정렬로 배치합니다.
- 섹션 제목과 값은 그룹별로 묶고 충분한 세로 간격을 둡니다.
- 야자시간과 방과후는 목록 화면과 동일한 색상 체계를 사용합니다.
- 상세 화면은 조회만 제공하며 승인·반려·취소 액션은 이번 범위에서 제외합니다.

### 역할별 진입

- 학생: 기존 `LabRentalPage`의 실습실 선택·대여 신청 흐름을 유지합니다.
- 선생님: 실습실 탭 선택 시 선생님 현황 목록 화면을 표시합니다.
- 역할 상태는 기존 `AccountRole`과 인증 흐름을 재사용하고, 화면 내부에 역할 판별 로직을 중복 작성하지 않습니다.

## 4. 데이터 및 아키텍처

```text
features/lab_rental/
├── domain/
│   ├── entities/lab_room.dart
│   ├── entities/lab_rental.dart
│   └── entities/teacher_lab_overview.dart
├── application/
│   ├── lab_rental_notifier.dart
│   └── teacher_lab_overview_notifier.dart
├── data/
│   └── mock_teacher_lab_overview_repository.dart
└── presentation/
    ├── lab_rental_page.dart
    ├── teacher_lab_overview_page.dart
    ├── teacher_lab_booking_detail_page.dart
    └── widgets/
```

- 기존 학생용 `LabRoom`, `LabRental` 모델과 대여 신청 상태는 변경 범위를 최소화하며 재사용합니다.
- 선생님 조회에 필요한 `TeacherLabRoomStatus`, `TeacherLabBooking`, 이용 유형, 층·날짜 조회 상태를 별도 모델로 분리합니다.
- `TeacherLabOverviewNotifier`는 선택된 층·날짜·목록 상태만 관리하고, 위젯에는 표시 상태와 이벤트 콜백을 전달합니다.
- `TeacherLabOverviewRepository` 추상화를 두고 현재는 목 Repository를 사용합니다.
- API 명세가 확정되면 Repository 구현만 교체할 수 있도록 화면에서 직접 목 데이터를 참조하지 않습니다.
- 예약 카드의 상세 이동은 Flutter 라우팅 또는 기존 Navigator 패턴을 따르며, 역할 판별과 데이터 조회 로직을 View에 작성하지 않습니다.

## 7. 제한사항 및 결정 필요 항목

- 실제 실습실 현황 API와 날짜 조회 파라미터가 확정되지 않아 초기 구현은 Mock Repository를 사용합니다.
- 선생님 화면의 예약 승인·반려 기능은 요청 범위가 아니므로 조회 전용으로 구현합니다.
- 날짜 선택을 실제로 제공할지, 서버 기준 날짜만 표시할지는 API 계약 후 확정합니다.
- 역할 정보가 현재 앱 전역 상태에서 어느 범위까지 전달되는지 구현 전 확인합니다.
- Android 프로젝트 작업 디렉터리에 기존 삭제 변경(`assets/images/outing-apply-illustration.png`)이 있어, 해당 변경은 이번 작업에 포함하지 않고 보존합니다.
