# 인증 진입 및 회원가입 UI 계획서

> **상태**: 구현 중
> **작성일**: 2026-08-11
> **작업 번호**: #02
> **관련 이슈**: [#3](https://github.com/GBSW-ReMake/GONE-AOS/issues/3)
> **브랜치**: `feat/3-auth-flow`

## 1. 목적 및 배경

GONE iOS 앱의 첫 진입 경험을 Flutter Android 앱에 구현합니다. 사용자는 GONE 시작 화면을 본 뒤 로그인 유형을 선택하고, 로그인 또는 회원가입 흐름을 이용할 수 있습니다.

## 2. 사용자 시나리오

```text
사용자가 앱을 실행한다
→ 스플래시 화면에서 GONE 로고 전환을 본다
→ 학생 또는 선생님 로그인 유형을 선택한다
→ 아이디와 비밀번호를 입력해 로그인한다
→ 계정이 없으면 회원가입을 선택한다
→ 회원가입 단계별 입력과 검증을 완료한다
→ API 미연동 안내를 확인한다
```

## 3. 구현 범위

### 화면

- Splash: GONE 로고, Reduce Motion 대응, 역할 선택 화면으로 이동
- Role selection: 학생/선생님 로그인 유형 선택
- Login: 아이디·전화번호, 비밀번호 입력, 입력 오류, 회원가입 이동, 역할 선택으로 돌아가기
- Signup: 아이디, 비밀번호·확인, 전화번호·인증번호, 학번·이름, 선택형 프로필 사진의 5단계 입력

### UX와 접근성

- 화면 상태는 정상, 입력 오류, API 미연동 안내를 제공합니다.
- 로딩, 빈 상태는 서버 호출을 연결하는 후속 작업에서 구현합니다.
- 버튼과 아이콘의 터치 영역은 48dp 이상으로 유지합니다.
- TalkBack 레이블, 비밀번호 보안 입력, 키보드 유형, 다크 모드, 글자 크기 확대를 적용합니다.
- Reduce Motion이 켜져 있으면 스플래시의 크기 전환을 생략하고 페이드만 적용합니다.

## 4. 데이터 및 아키텍처

```text
features/auth/
├── presentation/
│   ├── splash/
│   ├── role_selection/
│   ├── login/
│   └── signup/
├── domain/
│   └── entities/account_role.dart
└── application/
    └── auth_flow_notifier.dart
```

- `AuthFlowNotifier`가 splash, 역할 선택, 로그인, 회원가입 화면 전환 상태를 관리합니다.
- `LoginNotifier`와 `SignupNotifier`가 입력값, 검증 메시지, CTA 활성 상태를 관리합니다.
- 이번 단계에서는 실제 인증 API와 저장소를 추가하지 않습니다.
- 로그인 제출과 회원가입 완료는 API 연결 필요 안내를 표시합니다.
- API 계약이 확정되면 `AuthRepository`, `SignInUseCase`, `SignUpUseCase`를 추가합니다.

## 5. Figma 반영 기준

- 제공된 Figma 파일의 루트 노드(`0:1`)는 화면 레이어를 반환하지 않아 디자인 속성을 읽지 못했습니다.
- 로그인, 회원가입, 스플래시 각각의 화면 노드 URL을 받으면 간격, 타이포그래피, 색상, 에셋을 구현 전 확정합니다.
- 화면 노드가 제공되기 전에는 iOS 구현과 `doc/DESIGN_SYSTEM.md` 토큰을 기준으로 Android에 맞게 구성합니다.
