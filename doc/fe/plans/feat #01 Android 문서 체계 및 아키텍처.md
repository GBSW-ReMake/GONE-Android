## 1. 목적 및 배경

GONE iOS 프로젝트와 같은 기준으로 Android 개발 기록을 관리합니다. Flutter 프로젝트에 맞는 계층 책임과 상태 관리 원칙을 먼저 정해 이후 기능 구현의 구조를 일관되게 유지합니다.

## 2. 사용자 시나리오

```text
개발자가 새 기능을 계획한다
→ 계획서와 완료 기준을 작성한다
→ 검토 후 GitHub 이슈와 기능 브랜치를 만든다
→ QA와 최종 보고서를 남기고 PR을 요청한다
```

## 3. 문서 및 UX 기준

- iOS와 동일하게 `plans`, `issues`, `reports` 폴더와 템플릿을 제공합니다.
- Android UI 문서는 Material 3, 48dp 터치 영역, TalkBack, 다크 모드, 글자 크기 확대를 기준으로 작성합니다.
- 계획서와 QA 문서에는 정상, 로딩, 빈 상태, 오류, 권한 거부 상태를 기록합니다.

## 4. 데이터 및 아키텍처

- 기능 폴더를 기준으로 `presentation`, `application`, `domain`, `data`를 분리합니다.
- 화면 상태는 Riverpod `Notifier` 또는 `AsyncNotifier`가 관리합니다.
- 외부 I/O와 재사용 비즈니스 규칙에만 Repository와 UseCase를 적용합니다.
- Flutter, Riverpod, 네트워크 구현은 Domain 계층에 의존하지 않습니다.
